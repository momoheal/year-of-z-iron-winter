### 3.1 投影规则 —— 最容易做错的一步

关卡坐标 → 像素的换算（`build_scene.py:38-46`）：

```python
PPM, SQ = 64.0, 0.62          # 每逻辑米 64 px；地面纵深压缩 0.62
GY = PPM * SQ                 # = 39.68 px / 米（纵深方向）
```

`SQ = 0.62` 对应 75° 俯角的地面压缩。**贴花要落在地面平面上，就必须服从这个压缩。**

**正确做法**：贴花按**正俯视 1:1** 出图，运行时施加 `diag(1, SQ) · R(θ)` 变换：

```gdscript
const SQ := 0.62

## 把贴花放到地面平面上：先按 θ 旋转，再在**世界 Y 轴**上压缩 0.62。
## 不能用 spr.rotation + spr.scale.y —— Godot 节点变换是 T·R·S，
## 缩放作用在局部坐标系里，会跟着旋转一起转：朝北的脚印会被沿世界 X 压扁。
func _ground_transform(angle: float, at: Vector2) -> Transform2D:
	var r := Transform2D(angle, Vector2.ZERO)          # 纯旋转，无平移
	return Transform2D(
		Vector2(r.x.x, r.x.y * SQ),                    # 列向量各自乘 diag(1, SQ)
		Vector2(r.y.x, r.y.y * SQ),
		at)
```

**这样做的收益**：一张正俯视图能服务所有朝向（脚印 360°、车辙任意拐弯），不必预烘 8 个方向。**代价**：出图时必须按正俯视画，不能预先画扁 —— 这一点要在出图前和美术说清，否则会双重压缩。

> ⚠️ **θ 必须是"地面角"，不是"像素角"。**
> 矩阵里已经包含压缩了，所以传进去的旋转角要在**未压缩的地面空间**里量。
> 玩家脚本里的 `player.facing` 恰好就是地面角 —— `NightPlayer.gd:49` 用
> `atan2(m.y / SQ, m.x)` 先把鼠标方向反压缩过了，`_aim_vec()` 也是
> `Vector2(cos(facing), sin(facing))`。**直接喂 `player.facing`，不要再除一次 SQ。**
>
> 反过来，`NightExplore._m_dir_px()`（第 1584 行，`Vector2(dir.x, dir.y * SQ).normalized()`）
> 返回的是**像素空间**方向，拿它去求 `atan2` 当旋转角，就会把压缩做两遍 —— 这是本方案
> 最容易踩的第二个坑。它适合用来算射线终点，不适合用来算贴花朝向。


### 3.2 静态贴花（B / C 类）：`PROPS` schema 扩展

`levels/<id>.py` 的 `PROPS` 条目加一个可选键 `decal`，值是该贴花在 `$Decals` 内的 `z_index`（同位置多张叠放时定先后）：

```python
dict(id="SnowPileNW",   art="VFX_Decal_Snow_Pile_C",    pos=(0.9, 2.2),  decal=0),
```

`build_scene.py` 在道具循环（现第 196 行）之前分流：

```python
for p in LY.PROPS:
    if "decal" in p:                      # 贴花：裸 Sprite2D，无碰撞、无遮光、不参与 y-sort
        n = S.node(p["id"], "Sprite2D", "Decals",
                   position=v2(px(*p["pos"])), light_mask="2",
                   z_index=str(p.get("decal", 0)))
        sprite(n, p["art"])
        continue
    # ... 原有 StaticBody2D 分支不动
```

关键点三条：
1. **必须进 `Decals`，不能进 `World/Props`** —— 后者开了 `y_sort_enabled`，贴花会被 y-sort 排到角色前后，出现"贴在脚上的血泊盖住靴子"。

3. **pivot 取"接地中心"**（脚底中点），与 `PRP_*` 同一约定；`sprite()` 依赖 manifest 的 `pivot`，所以新贴花必须登记进 `night_<level>_manifest.json`。

### 3.3 运行时贴花（A 类）：两个池子，不是一个大池

现有 `_splat()` 没有任何上限 —— 一夜下来血溅会无限累积成节点。但**简单地加一个总数上限也是错的**：

> 玩家走 1000 步产出上千个脚印，如果和血泊共用一个 FIFO 池，脚印会把「刚杀死狂暴者留下的血泊」挤掉 —— 而血泊是玩家会回头看的东西。

所以拆两个池：

| 池 | 成员 | 上限 | 回收策略 |
|---|---|---|---|
| `marks` | 血泊、弹孔、碎玻璃 | **48** | FIFO，本夜不淡出（战斗留痕） |
| `tracks` | 脚印、车辙、拖痕 | **64** | FIFO + 25 s alpha 淡出 |

总节点 ≤ 112，纯 `Sprite2D`，开销可忽略。

```gdscript
const DECAL_MARKS_CAP := 48
const DECAL_TRACKS_CAP := 64
const DECAL_TRACK_FADE := 25.0

var _marks: Array[Sprite2D] = []     # 血泊 / 弹孔 / 碎玻璃：本夜不淡出
var _tracks: Array[Sprite2D] = []    # 脚印 / 车辙 / 拖痕：淡出

## pool: "marks" | "tracks"。angle 为**地面角**（未压缩）。
func add_decal(tex_path: String, at: Vector2, angle := 0.0,
		pool := "marks", fade := 0.0) -> Sprite2D:
	var s := Sprite2D.new()
	s.texture = load(tex_path)
	s.light_mask = 2                       # 与 Ground 一致，由地面灯照亮
	s.transform = _ground_transform(angle, at + Vector2(0, -4))
	$Decals.add_child(s)

	var arr: Array = _marks if pool == "marks" else _tracks
	var cap: int = DECAL_MARKS_CAP if pool == "marks" else DECAL_TRACKS_CAP
	arr.append(s)
	while arr.size() > cap:
		var old: Sprite2D = arr.pop_front()
		if is_instance_valid(old):
			old.queue_free()

	if fade > 0.0:
		var tw := s.create_tween()
		tw.tween_property(s, "modulate:a", 0.0, fade).set_delay(fade * 0.4)
		tw.tween_callback(s.queue_free)
	return s
```

> 不提供运行时缩放参数：20 张图已经按 §2 的尺寸定死，缩放只会让像素密度不一致，
> 而且 `scale` 与 `transform` 会互相覆盖（`scale` 是 `transform` 的派生属性）。
> 需要更大就重出图。

顺带把 `_splat()` 改成调用它，保持 `night_explore_smoke.gd:268` 的断言继续成立：

```gdscript
func _splat(pos: Vector2) -> void:
	add_decal("res://art/50_vfx/VFX_Decal_Blood_Pool_M.png", pos, rng.randf_range(-0.2, 0.2))
```

### 3.4 脚印系统：复用已有的脚步节拍，不要另起一套距离判断

`NightPlayer.gd:57-66` 里已经有一个脚步声节拍器 `_step`：

```gdscript
	# 脚步噪声
	if moving:
		_step -= delta
		if _step <= 0.0:
			var r := NOISE_SNEAK if crouching else (NOISE_SPRINT if sprinting else NOISE_WALK)
			if on_slush:
				r *= 2.0
			ctl.emit_noise(global_position, r, "step")
			_step = 0.62 if crouching else (0.3 if sprinting else 0.45)
	else:
		_step = 0.0
```

**注意 `_step` 的单位是秒，不是米。** 折成实际步距（查 `NightPlayer.gd:9-11` 的速度常量）：

| 姿态 | 速度 | 节拍 | 实际每印距离 |
|---|---|---|---|
| 潜行 `crouching` | 1.15 m/s | 0.62 s | **0.71 m** |
| 步行（默认） | 2.6 m/s | 0.45 s | **1.17 m** |
| 冲刺 `sprinting` | 4.4 m/s | 0.3 s | **1.32 m** |

**所以正确的接入点是这个 `if _step <= 0.0:` 分支**——脚印和脚步声在同一帧落下，听觉与视觉才同步。另写一个按米数累计的独立判断，会和脚步声错拍，走起来像"看到脚印之后才听到声音"。

```gdscript
# NightPlayer.gd —— 只加两行，其余不动
		if _step <= 0.0:
			var r := NOISE_SNEAK if crouching else (NOISE_SPRINT if sprinting else NOISE_WALK)
			if on_slush:
				r *= 2.0
			ctl.emit_noise(global_position, r, "step")
			ctl.footprint(global_position, facing)      # ← 新增：与脚步声同帧
			_step = 0.62 if crouching else (0.3 if sprinting else 0.45)
```

```gdscript
# NightExplore.gd
var _step_left := true

## 落一只脚印。facing 是**地面角**（NightPlayer 里已反压缩过），直接喂给 _ground_transform。
func footprint(at: Vector2, facing: float) -> void:
	var tex := "res://art/50_vfx/VFX_Decal_Footprint_Boot_%s.png" % ("L" if _step_left else "R")
	_step_left = not _step_left
	var jitter := Vector2(rng.randf_range(-2.0, 2.0), rng.randf_range(-1.0, 1.0))
	add_decal(tex, at + jitter, facing, "tracks", DECAL_TRACK_FADE)
```

要点：

- **左右交替**（`_step_left` 翻转），否则看起来像单脚蹦。
- **角度用 `facing`**，不要用移动方向再算一遍 —— `facing` 跟随鼠标，蹲着侧身走时脚印朝向应与身体一致，而不是与位移一致。这既符合直觉，也省掉一次 `atan2`。
- **落点加抖动**（x ±2 px、y ±1 px），避免出现"尺子量过"的一条直线。
- **伙伴**（`NightFollower`）用 `A3` 爪印：它有自己的移动循环，同样按节拍落印，但间距放大到约 1.4 m（四足步幅更小、频率更低，观感上不会糊成一片）。
- **只在室外雪地落印**。室内关（食堂、冷库、锅炉房）地面是水泥，脚印不成立。判断依据用 `_read_level_meta()` 已经读到的关卡 id，配一张室内关清单；`on_slush` 白名单不适用（雪泥只是地面的一种）。
- **清杀队 / 狂暴者不落印**。它们不是玩家该追踪的目标，加了只会变成视觉噪声。

> 顺带一个坑：`NightPlayer` 的速度是 `Vector2(dir.x * PPM, dir.y * PPM * SQ) * spd`（第 46 行），
> 也就是 `global_position` 活在**压缩后的像素空间**里。所以任何"走了多远"的判断
> 都不能直接 `distance_to / PPM` —— 纵向会被高估 1/0.62 ≈ 1.6 倍。
> 现成的正确换算在 `NightExplore.gd:237`：`to_m(p) = (p.x/PPM, p.y/(PPM*SQ))`，
> 或直接用 `dist_m(a, b)`（第 240 行）。

## 6. 风险

| 风险 | 后果 | 处置 |
|---|---|---|
| 投影做错（用 `rotation` + `scale.y`） | 南北向脚印被压成一条横线；朝北的人走出横向扁印 | §3.1 的矩阵 + §5#3 的断言 |
| 旋转角用了像素角（`_m_dir_px` / `atan2(y*SQ, x)`） | 压缩做两遍，脚印变细长条 | 一律用 `player.facing`（已是地面角） |
| 用 `distance_to / PPM` 判断走了多远 | 纵向高估 1.6 倍，脚印间距忽大忽小 | 用 `to_m()` / `dist_m()`，或直接复用 `_step` 节拍 |
| 贴花漏设 `light_mask = 2` | 夜里地面上一块明显发亮，像贴了张纸 | 一律经 `add_decal()` / 构建器统一设置，不手写 Sprite2D |
| 静态贴花误放进 `World/Props` | y-sort 把血泊排到角色前面，盖住靴子 | §3.2 强制进 `Decals` |
| 单池 FIFO | 脚印挤掉血泊 | §3.3 两池隔离 |
| 双重压缩 | 出图时已按 0.62 画扁，运行时再压一次 → 变成一条线 | 出图规格里写明"正俯视 1:1，不预压缩" |
| 依赖没装 | `gen_vfx.py` 直接 ImportError | 批 1 第 1 步先装 |
| 重生成 8 个 .tscn | 二进制 diff 极大，review 困难 | 批 3 单独提交，且只改 `Decals` 子树 |
