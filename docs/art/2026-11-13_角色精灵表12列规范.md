# 角色精灵表 · 12 列规范与出图流程（2026-11-13）

> 本轮把 4 个角色的精灵表从 **8 列 / 24 帧** 重建为 **12 列 / 36 帧**，并统一换成极乐迪斯科式厚涂油画风、正常成人比例。
> 本文是**唯一真源**，出图、切帧、入库、改代码一律以此为准。

---

## 1. 硬规格（不可变项）

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| 画布 | **864 × 336** | 12 列 × 3 行 |
| 单帧 | **72 × 112** | 与旧版一致，场景缩放不需要重排 |
| pivot | **脚底中心 (36, 108)** | 落地线：帧内 alpha 下沿 = y107 |
| 行序 | `0 = S 正面` `1 = E 侧面朝右` `2 = N 背面` | 向左走用 `flip_h`，不单独出图 |
| 帧索引 | **`frame = row * 12 + col`** | 旧代码是 `row * 8 + col`，本次已全库替换 |
| hframes | **12** | 14 个 `night_*.tscn` 共 89 处已改 |

## 2. 列语义

| 列 | 玩家（CHR_01） | 敌人（CHR_03/04/05） |
| :--- | :--- | :--- |
| 0 | 待机 | 待机 |
| 1–7 | 行走（7 个推进帧） | 行走（7 个推进帧） |
| 8 | **行走循环闭合帧**（＝第 1 帧） | 同左 |
| 9 | 蹲伏待机 | 攻击预备 / 携枪瞄准 / 蜷缩 |
| 10 | 蹲走 A | 前扑 / 搜索 / 硬直 |
| 11 | 蹲走 B | **倒地尸体** |

- 第 8 列复制第 1 帧是行走循环的常规做法（8 帧播放时末帧回到起点姿势），不额外消耗一次出图。
- 敌人第 11 列必须是**躺在地上的尸体**：旧表把尸体塞在 6/7 列，导致走路缺帧，且尸体姿势一眼不像死的，玩家会误判成活敌。
- 敌人 9–11 列在三个方向行里**共用同一组图**（`--tail-all`）。躺尸、举臂、硬直这类姿势不依赖朝向；只有 OSK 携枪瞄准在背面行会略显正面，属可接受的取舍。

## 3. 出图流程（实测有效）

模型（GPT Image / 类 Flux）**画不好 12 列**，会退化成 8 列——这是本轮踩到的第一个坑。真正稳定的做法是：

1. **一个朝向出一张 `4 列 × 3 行 = 12 格` 图**（1024×1024）。这个网格模型能稳定交付。
   - 第 1 行：待机 + 3 个行走帧
   - 第 2 行：4 个行走帧（腿分得最开，是走路质量的主要来源）
   - 第 3 行：蹲伏 / 特殊姿势
2. 三个方向（S / E / N）各出一张，**用上一张当 `image1` 参考**保证同一角色。
   → 代价：参考图会把旧布局（8 列、第 3 行蹲伏）带进来，背面行的蹲伏会被画成正面。
3. 玩家角色另出一张 **横排 4 格**的「背面蹲伏」补图，用 `--tail2` 替换背面行第 10–12 列。
4. 敌人另出一张横排 4 格（攻击 / 前扑 / 倒地 / 备用），用 `--tail-all` 覆盖三行第 10–12 列。

### Prompt 关键句

- 风格：`oil painting, thick impasto brushwork, visible palette-knife strokes, coarse canvas texture, muddy desaturated palette of cold blue-grey, tar black and sickly ochre, dramatic chiaroscuro, film grain, painterly soft edges, semi-realistic`
- 负面：`not cartoon, not anime, not cel-shaded, not pixel art, not 3D render`
- 比例：`realistic adult human proportions, about seven heads tall, long legs, narrow shoulders, a normal-sized head. Not chibi, not big-headed, not short-legged`
  **必须写这句**，否则模型会照着旧参考图继续画成 1:3.5 的大头短腿。
- 布局：`a grid of exactly 12 panels, 4 panels across and 3 panels down, on a pure white background, evenly spaced, no text, no labels, no grid lines, no ground shadows`

## 4. 切帧工具

```bash
# 三个朝向 + 可选补图 → 864×336 精灵表
python godot_project/tools/sprite_assemble.py \
  --out sheet.png --preview preview.png \
  --row0 S.png --row1 E.png --row2 N.png \
  [--tail2 N_crouch.png]     # 只替换第 3 行第 10-12 列（玩家蹲伏）
  [--tail-all tail.png]      # 替换三行第 10-12 列（敌方特殊姿势）
```

工具做四件事：白底硬抠（`dist>45` + 1px 腐蚀，防止腿间封闭白块残留）→ 网格检测（区段数不对时按最窄间隙合并，再退化为内容包围盒等分）→ **全表统一缩放**（以行走列高度中位数为基准，帧间不会跳动）+ 脚底对齐 108 → 去掉脱离主体的孤立碎屑。

### 稳定出图配方（v2）

- 枪械必须逐件列举：`curved banana magazine / wooden buttstock / wooden handguard / gas tube / pistol grip / short cylindrical suppressor`，并点名 `NOT a Mosin-Nagant, NOT a shotgun`。

- 尸体必须写 `exactly TWO arms, TWO hands, TWO legs, ONE head, NO third or fourth arm`。
  **⚠️ 2026-11-14 修订**：v2 为规避网格切坏写成 `compact curled pose`，结果三张敌人表的尸体全变成「抱膝端坐」，背面行甚至出现跪姿活人（CHR_04 N 帧高 104px）。下一轮出图请改用

  宁可横躺细长被切，也不要一个看起来活着的尸体。

## v2.3 验收返工（2026-11-15 · 用户「弹夹和尸体都是错的」）

用户验收 v2.2 失败。重新逐帧检查确认两处硬错误，且 `check_chars.py` 57/57 是假阳性。
完整诊断与试错记录见 `docs/art/2026-11-14_精灵表v2复核.md` 第七节。

### 两条被推翻的 v2.2 结论

| v2.2 写法 | 实际 |
| :--- | :--- |
| 「亮银弹匣偏亮是为小尺寸可读性刻意提亮」 | 亮银大月牙约 10×25px（真弹匣近 2 倍）、浅蓝白软边，读成**布带 / 围裙**；且全表出现三把不同的枪 |
| 「尸体偏扁是横躺透视必然，不算故障」 | 源图合格，错在 `fit()` 按宽等比缩放把 2.1:1 压成 **62×30px** 贴底；站立帧 50×100px，死亡瞬间像缩成贴片 |

### 断言缺陷（根因）

`check_chars.py` 的「第 11 列帧高 ≤80」**只设上限、不设下限**，30px 扁片照样通过。
等于断言反过来逼着把尸体做扁。脚本只查尺寸上限与像素一致性，完全不查体量与视觉语义。

### 修正后的红线（57 → 60 条）

- 第 11 列帧高 **40~75px**（上限排跪姿活人，下限排贴地扁片）
- 第 11 列 **宽/高 ≥ 1.15**（保证横向躺姿）
- `apply_v21.py` 同步 `MIN_CORPSE_H = 40`、`CORPSE_STRETCH = 1.4`

红队验证：放回 v2.2 表 → 57 passed / **3 failed**（30 / 29 / 34px 三个扁片）；修正版 → 60 / 0。

### 新增两条出图 / 切帧经验

- **弹匣别用明度硬凑**：试过 72px 椭圆提亮（胸口亮斑）、月牙多边形 + 硬边（灰补丁 + 锯齿白线）、
  亮银掩膜精确提亮（灰盾牌）、1024 源图柔和羽化（浅灰补丁）—— 四种程序化增强全部失败。
  原因是掩膜总会把弹匣周围制服一起提亮，并抹掉金属内部明暗层次。
  **结论：退回标准深色源图，宁可 1x 读不出，也不要假的亮银布带。**
- **尸体别旋转**：旋转 20° / 28° / 35° 会把「躺平」变成「爬行 / 俯卧撑」，反而更像活人。
