## 二、硬故障

### P1 尸体帧不像尸体，且三个方向互相打架（最严重）

第 11 列的语义是**倒地尸体**，代码也是这么取的：

```
NightRabid.gd:150 / NightHalf.gd:113 / NightSoldier.gd:272
sprite.frame = sprite.frame - sprite.frame % 12 + 11   # 11 = 倒地尸体
```

它保留当前行方向，所以"背对玩家死掉"会直接取背面行第 11 列。实测三个方向的帧内高度：

| 角色 | 正面 S | 侧面 E | 背面 N | 问题 |
| :--- | ---: | ---: | ---: | :--- |
| 狂暴者 CHR_03 | 83 | 83 | 81 | 三向一致，但都是**抱膝缩成一团**，不像死尸 |
| 半人 CHR_04 | 66 | 66 | **104** | 背面是**双膝跪地、手臂下垂的活人** |
| 清杀兵 CHR_05 | 87 | 87 | 66 | 只有背面真躺下了，正面/侧面是抱膝坐着 |

对照图：`docs/art/check_2026-11-14_corpse.png`

- 玩家朝北打死的半人，尸体会**站起来跪着**，比原来"四只手"更容易误判成活敌。
- 正面/侧面与背面尺寸差 21–38px，转向时尸体会突然放大/缩小。
- 根因：v2 为了绕开"横躺细长被网格切坏"，把尸体改成"抱膝蜷缩"，结果**把"倒下"改成了"坐着"**；而背面行是用另一张补图覆盖的，那张图里画的是跪姿。

### P2 清杀兵 CHR_05 的侧面行 ≈ 正面行

量化：S 行与 E 行逐帧剪影 IoU **0.978**（其余三角色 0.70–0.80 属正常差异），第 4 帧与第 0 帧几乎是同一姿势重绘。只有第 9–11 列 S/E 有区别。

后果：OSK 向右移动时没有"转身"，看起来是横向平移。这是本轮唯一一个**方向可读性**问题。

对照图：`docs/art/check_2026-11-14_side.png`

## 七、验收返工（2026-11-15 · 用户「弹夹和尸体都是错的」）

**本节推翻第六节的两个结论**：第六节写的「亮银弹匣偏亮是为可读性刻意提亮」「尸体偏扁是透视必然」
都是误判。重新逐帧检查后确认用户是对的，且 `check_chars.py` 的 57/57 是假阳性。

### 7.1 弹匣：只改了 2 帧，且改过头

放大 c9/c10 后，那个「亮银弧弹匣」实测约 **10×25px**，从机匣垂到腰带，是 AK 弹匣正常尺寸的
近 2 倍；浅蓝白、边缘偏软，读起来是**挂在胸前的布带 / 围裙**，不是金属件。用「放大 1.5 倍 +
提亮」换 64px 可读性，等于牺牲形状语义换明度对比。

更严重的是**全表三把不同的枪**：

| 位置 | 枪 |
| :--- | :--- |
| S 行 c0–8 行走 | v2 老图，斜挎木托枪，弹匣被身体挡住，看不到 |
| E 行 c0–8 行走 | 真侧面网格里的枪，小直弹匣、无消音器 |
| c9 / c10 瞄准 | 带亮银大月牙 + 消音器的「第三把枪」 |

走路与瞄准会换枪；c9–11 三行又共用同一帧，背面行也是正面持枪。第六节把它写成「已知取舍」，
实际上是缺陷。

### 7.2 尸体：源图合格，错在切帧策略

三张源图本身是合格的 3/4 横躺人形（头、双臂、双腿齐全）。`apply_v21.py` 的 `fit()` 按
「宽 ≤64」等比缩放，把宽高比约 2.1:1 的图压成 **62×30px**，贴在 112px 高的格子最底部，
上方空 78px。站立帧约 **50×100px**，敌人一死高度掉到 30px，视觉上不是「倒下」而是
「缩成一张贴地贴片」。三张尸体尺寸 62×30 / 62×29 / 62×34，构图几乎一样。

**根因在断言**：`check_chars.py` 的「第 11 列帧高 ≤80」本意是排除 CHR_04 那个 104px 跪姿活人，
但只设上限、不设下限，30px 扁片照样通过。等于断言反过来逼着把尸体做成扁片。
57/57 通过只能说明「尺寸没越界 + 像素一致」，完全不查体量与视觉语义。上一轮看放大图时也
只判断了「是不是横躺」，没判断「在帧里占多大、和站立帧比例对不对」。

### 7.3 本轮修法与试错（全部程序化，未再调用图像生成）

弹匣试了三种程序化增强，**全部弃用**：

| 方案 | 结果 |
| :--- | :--- |
| 72px 帧上椭圆局部提亮 | 胸口打成一片亮斑，比弹匣本身还显眼 |
| 72px 帧上月牙多边形提亮 + 1px 亮边 | 灰色补丁 + 放大后呈锯齿白线 |
| 从亮银版提弹匣掩膜，精确提亮标准版 | 亮银弹匣比标准版大 1.5 倍，蒙版把周围制服一起提亮成「灰盾牌」 |
| 1024 源图上柔和羽化提亮 | 仍是胸前一块浅灰补丁，丢失弹匣内部明暗层次 |

结论：**程序化无法同时满足「小尺寸可读」和「金属真实感」**，不再硬凑。退回 14:28 / 14:29
标准尺寸深色弧弹匣源图，去掉「布带」这个明显错误；1x/2x 下对比度不足列为遗留。

尸体也试过错路：**旋转 20° / 28° / 35° 会把「躺平」变成「爬行 / 俯卧撑」**，更像活人，
弃用。最终采用**不旋转 + 纵向透视补偿 ×1.4**：源图略俯视造成的压扁被补偿回来，
得到 64×43 / 64×42 / 64×49px，保持水平躺姿且人形不变形。

### 7.4 断言修正与红队验证

`check_chars.py` 把单向高度上限换成**体量双向红线 + 横躺比**（57 → **60 条**）：

- 第 11 列帧高 **40~75px**：上限排除跪姿活人，下限排除 30px 贴地扁片
- 第 11 列 **宽/高 ≥ 1.15**：保证是横向躺姿
- `apply_v21.py` 内部断言同步加 `MIN_CORPSE_H = 40`

红队验证：把 v2.2 出图后的表放回 → **57 passed / 3 failed**，三条 FAIL 正好是三个扁片尸体
（30 / 29 / 34px）；恢复修正版 → **60 passed / 0 failed**。断言确实能抓住这次的问题。
