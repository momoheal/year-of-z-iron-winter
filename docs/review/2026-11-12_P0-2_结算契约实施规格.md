### 4.4 旧 Dictionary 兼容适配策略

现成范式是 `RaidConfig.gd`，照抄其结构即可：

- `from_dict(d) -> RaidConfig`（`RaidConfig.gd:30-52`）：逐键 `d.get(key, default)`，类型显式转换；`weapon` 兼容整张 Dictionary / id 字符串（`weapon_id_of():55-59`）。
- `to_dict() -> Dictionary`（:67-85）：输出**旧 cfg 键名**（`loc` / `day` / `seed` / `left` / `mate` / `pack_max` / `weapon` / `load` / `cold` / `danger` / `time` / `glasses` / `night` / `sound_on`）+ 新增 `raid_id`（:70）。
- 保持 `RaidBridge.cfg` 仍是 Dictionary（T01:34），`NightExplore._ready():264-279` 的 `cfg.get(...)` 读法不变。
- `weapon` 双形态：`CampaignSim.depart():337` 写的是 `best_weapon()` 整张表；`NightExplore.gd:1366-1367` 已兼容 Dictionary / String；`RaidSim._init():169` 按 Dictionary 读（`.get("ammo")` :170）。**改造不得把某一侧改成只接受单一形态**【代码】。
- `RaidResult` 同理提供 `from_dict()` / `to_dict()`，使旧 Dictionary 结果（如测试里手工构造）可被接受；但**收口后生产侧只应有一条路径构建结果**（架构评估:91-92）。
