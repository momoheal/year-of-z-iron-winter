# 夜潜交接契约：字段清单（T01）

> 对应《项目架构评估与下一阶段实施计划_2026-11-11》§4 / §10 的 T01。
> 记录的是 **T02/T03 改造前** 的真实读写口径（2026-11-11 初稿，2026-11-24 按 `fix/campaign-save-release-checks` 分支复核补齐），
> 以及 T02/T03 之后由哪个类型化字段承接。改造不改变任何数值或损失规则。

两条路径：

- **节点化夜潜**（地点带 `scene` 字段，如 yard）：`CampaignSim.depart()` → `RaidBridge.begin(sim, cfg)` →
  `NightExplore._ready()` 读 cfg → 夜潜结束 `NightExplore._return_to_campaign(reason)` → 战役结算。
- **旧灰盒**（无 `scene` 字段）：`depart()` 直接 `RaidSim.new(self, cfg)`，`Campaign._process` 跑
  `RaidSim.update()`，结束时 `finish_raid(raid.phase)`。

## 1. 出发配置 cfg（`CampaignSim.depart()` 组装）

## 3. 携带物（最容易双倍返还的地方）

- 出发：`depart()` 从 stash 扣 `load` 一次，`load` 本身保留（下次出发的默认值）。
- 灰盒：携带物留在 `raid.load`，夜里消耗时扣；结算时 **剩余部分无论哪种收场都归还**（含 downed / abort）。
- 节点化：water / asp / band 变成 `pack` 里的物品，can 变成 `cans` 计数。结算时 `refund_load = {}`，
  所以 water/asp/band 跟着 `pack` 走损失规则（extracted 全带回、dawn 隔项、downed/abort 全丢），
  **没扔完的罐头不归还**（现状如此，属于玩法规则，本次不改；如需归还另开平衡任务）。

## 4. 结算规则（`CampaignSim.submit_raid_result()`，唯一入口）

拒收（返回 `{}`、不改任何状态，原因写在 `last_rejection`）：结果为空（no_result）、没有 `raid_id`（no_raid_id）、当前局已结算（already_settled）、没有出发过（no_open_raid）、不是当前局（wrong_raid）、reason 非法（bad_reason）、地点不符（wrong_loc）。
节点化场景的 `frozen` 先归一成 `downed`；`cutscene` / `interaction` / `modding` 等非结束状态在 NightExplore 里直接忽略，不会提交。
接受后按顺序：良知 → 卌（含日志本）→ 音效开关 → 损失规则 → 归还 `refund_load` → `add_item(kept)` →
新武器对比 → 节点 `visits+1`、`left-0.5`（下限 0.05）→ 组 `last_report`（键与旧版完全相同）→
`raid = null`、`phase = "report"`、标记已结算。日期不在结算里推进，仍由「回 602 室」`to_base() + advance_day()` 负责。

损失规则（未改）：extracted 全保留；dawn 保留 pack 中下标为偶数的物品（0,2,4…）、hp−22（下限 6）；downed / abort 全丢。

## 5. 夜里写战役状态（T04 已收口）

- 2026-11-25 起，夜里不再直接写战役：
  - 节点化地点出发只建轻量当局容器 `RaidAttempt`（不再生成整张灰盒地图），剧情进度字段写在它上面；
  - NightExplore 的 `vasily_killed` / `mine_inscriptions_seen` / `redzone_mother_seen` 旗标与 `seen.night` 记在本地，随 `RaidResult.flags_set` / `seen_set` 提交；
  - 灰盒 RaidSim 的抉择良知（逐笔 `conscience_steps`）、卌（`tally_marks`）、`betrayed` / `glasses` 旗标（`flags_set`）、搜刮带走的节点余量（`node_left_delta`）攒在 RaidSim 上，由适配器带进结果。
- 这些在结算入口一次性入账，**任何收场都入账**（与原先「夜里实时写、放弃也不撤销」的效果一致），重复提交被拒所以不会重复入账。
- 唯一例外：灰盒夜潜进行中，战役界面上的良知 / 卌读数要到结算后才变化（灰盒是旧路径，不再新增玩法）。

## 6. 存档

`raid_id`、当前局 / 已结算标记只存在于内存，不写盘；`SaveGame.VERSION` 与 JSON 键不变。
夜潜中途本来就不存档，读档后不存在未结算局，旧结果一律拒收。
