## 1. 原则

- **先打通，再加料**：做任何新内容之前，先让它能在战役里被玩到。
- **数据只有一份**：物品、武器、同伴、剧情一律读 `CampaignData.gd`，夜潜场景不另存一套数值。
- **每一步都有测试**：每个任务都写明怎样算完成，并补自动化测试，四套测试必须全绿才进入下一步。
- **美术走管线**：改布局、改美术都通过 `tools/art_gen/` 重新生成，不在编辑器里手改生成出来的 `.tscn`，否则下次生成会被覆盖。

## 4. P1 · 把夜间货场接进战役（最高优先）

### 4.1 现有接口

- `CampaignSim.depart(L)`：扣除携带物，组装出发配置 `cfg`（地点、天数、携带物 `load`、武器 `weapon`、同伴 `mate`、背包上限 `pack_max`、寒冷系数 `cold`、夜长 `night`），然后创建 `RaidSim`。
- `CampaignSim.finish_raid(reason)`：读取 `raid.pack`、`raid.player.hp`、`raid.load`，结算物资、伤势和天数。`reason` 取 `extracted`、`downed`、`dawn` 或 `abort`。
- 难点：`sim` 是 `Campaign.gd` 里的局部对象（RefCounted），换场景时会随战役节点一起被释放。

### 4.2 设计

```
602 室 ──选「夜间广轨货场」──► CampaignSim.depart(yard)
                               │  仍然创建 RaidSim（只当数据容器，不运行它的模拟）
                               ▼
                  RaidBridge.begin(sim)       ← 新 autoload，持有 sim，防止它被释放
                               │
           change_scene → night_explore.tscn  ← 读 RaidBridge.cfg：携带物、武器、同伴、夜长、寒冷
                               │
       撤离 / 倒下 / 冻死 / 天亮 → RaidBridge.finish(result)
                               │  把背包、生命、良知、卌、救下半人数写回 sim.raid
                               ▼
                 sim.finish_raid(reason) → change_scene → campaign.tscn
                               │
                Campaign._ready() 先取 RaidBridge.sim，没有才新建 → 显示结算
```

## 7. P4 · 第二张图：西站调车场（`marshalling`，危险度 4）

### 7.1 为什么选它

- **复用多**：铁轨、闷罐车厢、信号灯、探照灯塔、铁丝网、雪泥都能直接用，新画的素材最少。
- **剧情顺**：它在剧情里由「安娜 + 古丽娅入队」那条选项解锁，离装甲列车「暴风雪号」和三号车厢更近，是追查拉娜（0420）的下一步。
- **玩法有新意**：调车场能做「会动的掩体」，即缓慢调车的车厢会改变视线和路线。这是货场没有的。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 换场景时战役状态丢失 | 回到战役后存档错乱 | `RaidBridge` 持有 `sim`；P1.10 的往返测试专门覆盖这一点 |
| 灰盒和新场景的数值口径不一致 | 同一个地点两种难度 | 所有数值读 `CampaignData`；货场接入后灰盒版只作后备 |
| 程序化美术和定妆图风格越拉越远 | 画面不统一 | 每次改动都和定妆图并排对比（截图工具里的角色对照机位）；立绘用你的原图 |
| 寻路的性能 | 多个 AI 同时算路径 | 格子 0.5 米、每 0.3 秒重算一次，48×40 米的地图开销可以接受；在 F3 调试层里显示耗时 |
| 无人值守时重新生成覆盖了手工修改 | 编辑器里的修改丢失 | 场景一律由管线生成；P0 之后有 git 可以回退 |
